# 环境参数引用：{{组.参数}} 与测试环境

## 原则

**用例与环境解耦**：服务器地址、端口、APN、账号、密码、URL 等部署相关值一律引用 AICom「测试环境」配置，禁止硬编码。换测试环境只改配置，用例零改动。

## 两种引用

| 写法 | 解析来源 | 用途 |
|---|---|---|
| `{{组.参数}}` | 仅测试环境配置 | 服务器/账号等环境值 |
| `{{var}}` | ① 用例变量池 → ② 测试环境 default 组 | 上一步 extract 提取的结果 |

规则：
- `{{a.b.c}}` 两级以上点号 → 解析期直接报错
- 引用的组不存在 → 执行时本步渲染失败，报告 FAIL 且原因明确（「变量 X 未定义」）
- 模板只做字符串替换，**没有**表达式、默认值、条件语法——参数必须在测试环境中真实存在

## Agent 操作流

1. 写用例前 `testenv_get`（无参看全部分组，或指定组名）确认现有分组与参数
2. 需要的分组不存在 → 提示用户在 AICom「测试环境」页添加，或**经用户同意**后 `testenv_set` 写入
3. 值允许先放占位（如文档保留地址 `192.0.2.1`），但汇报时必须列出用例引用的全部「组.参数」清单，提醒用户填真实值
4. 用例中只写 `{{组.参数}}`，永远不写具体值

## 常用分组建议

| 组名 | 典型参数 | 引用示例 |
|---|---|---|
| `tcp` | host, port | `{{tcp.host}}` |
| `ssl` | host, port, ca, cert, key | `{{ssl.port}}` |
| `mqtt` | host, port, username, password | `{{mqtt.username}}` |
| `ftp` | host, user, pass | `{{ftp.user}}` |
| `default` | 兜底组（`{{var}}` 的二级查找目标） | `{{apn}}` |

以 `testenv_get` 实际返回为准；分组支持自定义与层级归组，用例只关心组名和参数名。

## 反面示例

```yaml
# 错：硬编码——换环境就得改用例，还泄露服务器信息
- command: 'AT+QIOPEN=1,0,"TCP","42.193.120.5",8000'

# 对：环境引用——值由 AICom「测试环境」页管理
- command: 'AT+QIOPEN=1,0,"TCP","{{tcp.host}}",{{tcp.port}}'
```
