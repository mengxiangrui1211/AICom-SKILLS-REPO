# 新平台接入：勘测五步法

「平台」= 一个具体模组型号/固件版本。第一次为它生成用例前，先完成本流程——
直接盲写断言是臆测，臆测的断言必失败。

## 第 1 步 · 文档来源确认

- 向用户拿到：指令集文档（手册章节/PDF/文本）+ 固件版本号
- 指令分两类处理：
  - **标准指令**（3GPP TS 27.007/27.005 覆盖：CSQ / CEREG / CGATT / CGDCONT / CMGF 等）
    → 响应格式跨平台基本一致，可先用 response-patterns.md 通用层规律起草
  - **厂商扩展指令**（前缀即厂商标识，如 QIOPEN / MIPCALL / MGRECEV 等）
    → 逐条查平台文档：响应格式、URC 时机、错误码体系都以平台手册为准

## 第 2 步 · 响应勘测（设备在线时）

对代表性指令用 `serial_write` 实测（**先征得用户同意**），记录：
- 前缀大小写与冒号后空格（`+CSQ: ` vs `+CSQ:`）
- 行帧与 CRLF 形态、是否有附加空行
- URC 出现时机（受理即回 OK、业务结果后到）
- 错误码体系（+CME ERROR / +CMS ERROR / 厂商自定义码表）

新发现**写回 `response-patterns.md` 对应平台小节**（活知识库，越测越准）。
设备不在线：先按文档写断言，在用例 description 标注「待实测校准」，并在汇报中单列这些用例。

## 第 3 步 · 环境参数表

清点该平台用例需要的外部参数（TCP/SSL/MQTT/FTP 服务器、APN、账号），对照 `testenv_get` 现状：
- 缺失分组 → 提示用户在「测试环境」页配置，或经同意后 `testenv_set` 写入
- 产出「平台 × 组.参数」清单，附在最终汇报里

## 第 4 步 · 归档约定

- 平台专属用例（厂商扩展指令 / 依赖平台行为的指令）：
  文件名 `<平台>-<功能块>-<指令>-<类型>-<变体>.yaml`，tags 首段平台名 `[<平台>, <功能块>, ...]`
- 跨平台通用用例（纯标准指令）：不加平台段
- 用例目录保持平铺，`testcase_list` 返回含 tags，按首段归组即得平台视图

## 第 5 步 · 校准生成

1. 先生成 **1 条探路用例**（如最简单的 CSQ 查询），请用户 `testcase_run` 实跑（或经同意由你执行）
2. 按报告里每步「实际响应」原文校准断言——重点是字节级 `matches`（前缀、空格、CRLF）
3. 校准通过 → 批量生成其余用例 → 逐个 `testcase_save` 入库
4. 按清单汇报：覆盖矩阵（指令 × 场景）/ 待实测校准项 / 环境参数清单 / 探路用例实跑结论
