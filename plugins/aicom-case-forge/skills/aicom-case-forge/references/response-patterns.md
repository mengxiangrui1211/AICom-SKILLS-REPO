## 通用层 · 标准指令（3GPP TS 27.007 / 27.005）

### 终结形态

- 最终结果码只有四种：`OK` / `ERROR` / `+CME ERROR: <err>` / `+CMS ERROR: <err>`
- 行以 `\r\n` 分帧；AICom 引擎把完整响应规整为 `\r\n` 包围的行块（指令自身的回显行会被过滤），
  字节级断言形如 `'^\r\n+CSQ: 20,99\r\nOK\r\n$'`
- 中间响应行（信息文本 / 业务码行）在最终结果码之前

### 前缀与空格

- 业务码响应以前缀 `+<指令名>:` 开头（如 AT+CSQ → `+CSQ: `）
- 冒号后通常一个空格，个别平台无空格——正则写 `\+CSQ:\s*(\d+)` 容忍差异；
  字节级 `matches` 则以实测为准
- 信息文本响应（ATI、AT+CGMM 等直接回文本）无 `+` 前缀，文本行 + OK 收尾

### 典型值域

| 指令 | 响应 | 合法域 |
|---|---|---|
| AT+CSQ | `+CSQ: <rssi>,<ber>` | rssi 0..31（99=未知）；ber 0..7（99=未知） |
| AT+CREG? / AT+CEREG? | `+C..EG: <n>,<stat>[,...]` | stat：0 未注册 / 1 本网 / 2 搜索中 / 3 拒绝 / 4 未知 / 5 漫游 |
| AT+CPIN? | `+CPIN: <code>` | READY / SIM PIN / SIM PUK / SIM PIN2 / SIM PUK2 / … |
| AT+CGATT? | `+CGATT: <state>` | 0 / 1 |

### 错误码

- `+CME ERROR: <err>`：参数/设备相关错误。断言错误码用 extract + `eq` 而非全文 matches
  （数字在不同平台/固件可能有差异），或直接断言 `matches: '\+CME ERROR'`
- `ERROR`（不带前缀）= 通用失败；同一指令两类错误都可能出现时，断言「非 OK 的终结形态」要写全
- 响应等待超时兜底：引擎终结只认四种结果码，纯业务码结尾（无 OK）的异常形态
  给步骤加小 `timeout`（如 1.2s）让它快速失败
